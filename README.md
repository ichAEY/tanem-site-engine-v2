# TANEM Site Engine v2

Центральный статический engine для массового производства цифровых офисов мастеров. Код один, данные и фотографии каждого клиента изолированы в отдельном репозитории.

Текущий выпуск `v0.1.0` покрывает сайты мастеров. Салон `stluxe` остаётся отдельным следующим шаблоном и в этот выпуск не смешивается.

## Что уже стандартизировано

| Ситуация | Поведение engine |
|---|---|
| 1–2 категории услуг | Вкладки занимают доступную ширину, как у Нонны |
| Категорий или названий много | Вкладки автоматически переходят в горизонтальную прокрутку, как у Юлии |
| Цена зависит от длины волос | `price.type: "variants"` выводит короткие, средние и длинные волосы |
| Акций нет | Раздел полностью отсутствует |
| Контактов больше двух | Выводится любое число типизированных контактов |
| Разная специализация | `specialty` выбирает правильную мобильную композицию; свои изображения задаются данными |
| Обычный прайс длинный | В выбранной категории сначала показываются пять услуг, остальные открываются кнопкой |
| У мастера по волосам больше двух категорий | Вкладка «Все» включается автоматически: сначала 9 услуг на компьютере и 6 на телефоне; выбранная категория раскрывается целиком |
| Задан ID Яндекс Метрики | Счётчик подключается автоматически; без ID сторонний скрипт не загружается |

Все варианты проходят через одну разметку. Персональные патчи и копирование старого сайта не нужны.

## Структура

- `src/` — единый дизайн и поведение;
- `site.json` — текущая тестовая конфигурация;
- `examples/` — проверенные структуры Нонны, Тахмины и Юлии;
- `site.schema.json` — машиночитаемая схема для редактора и ChatGPT;
- `fixtures/` — изображения только для эталонных тестов;
- `templates/client/` — минимальная основа отдельного клиентского репозитория;
- `scripts/` — проверка данных, выборочная упаковка файлов и настройка Pages.

После генерации страницы в `dist/` копируются только изображения выбранного клиента. Файлы остальных примеров в готовый сайт не попадают.

## Проверка engine

```bash
npm ci
npm test
npm run build:tahmina
npm run build:julia
```

Сборка останавливается, если схема данных нарушена, файл потерян, одно изображение тяжелее 450 КБ, код тяжелее 260 КБ или весь сайт тяжелее 4 МБ.

## Новый клиентский репозиторий

```text
site.json
assets/
  portrait.webp
  mobile-visual.webp
  portfolio/...
.github/workflows/pages.yml
AGENTS.md
README.md
```

1. Скопировать содержимое `templates/client/`.
2. Взять ближайшую структуру из `examples/`, заменить все данные и привести пути к виду `assets/...`.
3. Положить только клиентские изображения в `assets/`.
4. Указать `deployment.customDomain`, если используется домен TANEM.
5. Отправить в `main`. Workflow скачает строго закреплённый tag engine, проверит и опубликует сайт.

Работающая версия не заменяется, если новая сборка не прошла проверки.

## GitHub Pages и домен

После первого push Pages включается один раз токеном владельца репозитория:

```bash
node scripts/configure-pages.mjs ichAEY/CLIENT_REPO client.tanem.ru
```

Затем для конкретного поддомена создаётся отдельная DNS-запись `CNAME`, указывающая на `ichAEY.github.io` без имени репозитория. Не используйте wildcard `*.tanem.ru`: GitHub предупреждает о риске перехвата незанятых поддоменов.

При публикации через GitHub Actions файл `CNAME` не настраивает домен, поэтому домен задаётся через Pages API командой выше. HTTPS включается после выпуска сертификата.

## Массовый выпуск

Короткий готовый запрос находится в [FACTORY-PROMPT.md](FACTORY-PROMPT.md). В нём меняются только источник, репозиторий, домен и специализация. Правила отображения категорий, услуг и цен уже находятся в engine и не повторяются в каждом запросе.

Для полного цикла «ссылка → проверенный сайт → GitHub → публикация» нужен режим с доступом к браузеру, файлам, командам и GitHub. Astra не обязательна для серийного выпуска: после фиксации шаблона задача становится повторяемой. Обычный Chat подходит для подготовки текста и `site.json`, но сам по себе не гарантирует запуск тестов и публикацию репозитория.
